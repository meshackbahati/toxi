# Plan: Toxi -> Toxi Framework Overhaul

## Context

The Toxi Rust web framework has a critical WebSocket bug in production (CodeBana), several architectural concerns, and needs a full rename to "Toxi". The WebSocket issue manifests as `"Connection error: invalid HTTP method parsed"` on the server when clients connect via `wss://`. This plan covers all requested work.

---

## Part 1: CRITICAL - WebSocket Fix

### Root Cause Analysis

The server log `"Connection error: invalid HTTP method parsed"` comes from **hyper's HTTP parser** at `toxi-core/src/server.rs:233`. This error means hyper received bytes it couldn't parse as a valid HTTP/1.1 request.

**Most likely cause:** The reverse proxy (nginx or AWS ALB) in front of `api.codebana.g24sec.com` is terminating TLS and forwarding to the Toxi backend over **HTTP/2**. But the Toxi server only uses `http1::Builder` (server.rs:215), which expects HTTP/1.1 requests. HTTP/2 binary frames look nothing like HTTP/1.1 text requests to the parser.

**Why WebSocket specifically:** WebSocket upgrade requires the `Upgrade: websocket` + `Connection: upgrade` headers, which only work over HTTP/1.1. HTTP/2 uses a different mechanism (RFC 8441 Extended CONNECT). The proxy may also be stripping/mangling upgrade headers.

### Fix Implementation

**File: `toxi-core/src/server.rs`**

1. Add ALPN protocol negotiation to enable HTTP/2 when TLS is used (the server currently has no HTTP/2 support outside `tls.rs`)
2. Add a `Server::builder()` method that allows configuring HTTP version preference
3. In the main `listen()` method, detect HTTP/2 via ALPN and use `http2::Builder` when negotiated

**File: `toxi-core/src/server.rs` - BodyAdapter**

4. Ensure `BodyAdapter` handles HTTP/2 connections correctly (the body type conversion from `Incoming` should work for both, but verify)

**File: `toxi-core/src/tls.rs`**

5. Fix `listen_https()` to properly support ALPN negotiation for HTTP/1.1 and HTTP/2 auto-detection
6. Currently `HttpVersion::Auto` just falls back to HTTP/1.1 (line 186-189) - this should actually negotiate via ALPN

**File: `toxi-core/src/server.rs` - Connection error logging**

7. Improve the error logging at line 219-235 to distinguish between:
   - HTTP/2 frames on HTTP/1.1 parser (log a helpful message about proxy configuration)
   - Actual protocol errors
   - Client disconnections (already filtered)

### Proxy Configuration Guide (documentation)

Both HTTP/2 support AND proxy documentation will be provided:

8. Add a section to README or a new `docs/proxy-setup.md` with:
   - nginx WebSocket proxy config (`proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade";`)
   - AWS ALB WebSocket configuration
   - Cloudflare WebSocket configuration

## Part 2: Areas of Concern Fixes

### 2a. SQL Injection in Savepoints

**File: `toxi-db/src/lib.rs`**

- `create_savepoint()` (line 710-714) uses `format!("SAVEPOINT {}", name)` - the `name` parameter is a public API argument
- `rollback_to_savepoint()` (line 718-722) same issue
- `release_savepoint()` (line 726-730) same issue

**Fix:** Add identifier validation (reusing the existing `is_valid_identifier` function) to savepoint name parameters. Reject names containing spaces, quotes, semicolons, or other SQL metacharacters. Better: validate against a strict `[a-zA-Z0-9_]+` regex pattern since savepoint names should be simple identifiers.

### 2b. Config Env Var Handling

**File: `toxi-config/src/lib.rs`**

The config system is actually well-designed - it has sensible defaults for everything:
- `Config::default()` works without any env vars
- All config sections have `#[serde(default)]` and default functions
- `Config::load()` returns defaults if no `toxi.toml` exists

**After rename to Toxi:**
- The config file is named `toxi.toml` (line 749) -> becomes `toxi.toml`
- The `OXIDITE_ENV` and `OXIDITE_SKIP_DOTENV` env vars (lines 741, 745) -> `TOXI_ENV` / `TOXI_SKIP_DOTENV`
- The `default_app_name()` returns `"toxi-app"` (line 270) -> `"toxi-app"`

### 2c. Handler Impl Ordering

**File: `toxi-core/src/router.rs`**

The Handler impls are currently ordered: `()`, `(T1..T9)`, `(T1..T10)`, `(T1..T11)`, `(T1..T12)`, `(T1,T2)`, `(T1..T3)`, `(T1..T4)`, `(T1..T5)`, `(T1..T6)`, `(T1..T7)`, `(T1..T8)`.

**Fix:** Reorder to sequential: `()`, `(T1)`, `(T1,T2)`, ..., `(T1..T12)`.

### 2d. CORS Double-Header Issue

**Files: `toxi-core/src/router.rs` + `toxi-core/src/server.rs`**

Both the `Router` (line 697-733, `add_cors_headers`) and `BodyAdapter` (line 47-81, `add_cors_to_response`) add CORS headers. If CORS is configured on both levels, headers get doubled.

**Fix:** Remove CORS from `Router::add_cors_headers` and keep it only in `BodyAdapter` (server-level). The router should handle route matching only. Alternatively, add a guard to skip adding CORS in the router if it detects the response already has the header.

### 2e. Regex Routing - No change needed now

The regex approach works correctly. Replacing with `matchit` is a performance optimization that can come later. Note it for future work but don't change it in this refactor.
